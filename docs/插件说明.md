# Method 插件说明

这份文档回答：`/method` 模式做什么、怎么用、要交什么样的计划、拦什么不拦什么、计划长什么样、有哪些限制。

## 包与装配

| 项 | 内容 |
| --- | --- |
| 包目录 | 仓库根目录 |
| 入口 | 仓库根目录的 `index.js`：接收插件上下文，把投影、提示词段落、命令、工具挂上去 |
| 依赖 | 只用 Node 自带的加密、文件、路径三类模块；不装宿主运行时包，只靠 profile 自身解析 |
| 安装形态 | 本仓库未发布到 npm，需 clone 后以 link 方式挂进 web profile 的 bundle 列表 |
| 用到的宿主能力 | 工具、系统提示词段落、会话投影是必需项；命令与计划模式可选，缺了照样激活，只是没有进出方式 |

安装步骤：

```sh
git clone https://github.com/LMQ00/dsh-method.git ~/Projects/dsh-method
dsh plugin --profile web add link:~/Projects/dsh-method
```

装完重启 `dsh web`。profile 的 `node_modules` 里应有 `dsh-method` 软链；缺这条软链时 `dsh web` 会打印 `cannot resolve profile bundle "dsh-method"` 并跳过该 bundle，重装一次即可。

## 命令与状态

在网页输入框直接输入：

```sh
/method
/method off
```

| 当前状态 | `/method` 的行为 | 回执 |
| --- | --- | --- |
| 未启用 + 无参 | 只进入模式，不提交任何消息；注入一行提示说明协议已生效 | `Method mode on. 直接说要做的事，我先产出结构化计划。` |
| 未启用 + 带内容 | 进入模式，并把内容作为这一轮的用户消息提交 | `Method mode on.` |
| 已启用 + 无参 | 只回执并再注入一行提示，不提交消息 | 同上 |
| 已启用 + `off` | 退出模式；计划保留在盘上但不再强制 | `Method mode off.` |
| 未启用 + `off` | 什么都不做，状态不变 | `Method mode 未开启。` |
| 计划模式活跃 + 进入 | 拒绝进入（只在未启用时检查），状态不变 | `Exit plan mode first.` |

状态从会话日志折叠得出，恢复、分叉、重放都能还原这个会话的模式与最近一次被接受的计划。

- 进入模式后协议走系统提示词段落，不展开在对话里，不占对话 token。
- 退出模式不删计划文件：`.method/plan.md` 留着，作为记录。

## 计划必须包含什么

模型通过 `plan_submit` 提交，不是写文档。结构由 schema 与校验器强制，缺项直接被拒。

| 项 | 要求 |
| --- | --- |
| 目标 | 一句话说清完成后的状态，非空 |
| 非目标 | 至少 1 条明确不做的，互相不重复 |
| 约束 | 至少 1 条，每条标 `hard`（违反即失败）或 `soft`（可协商） |
| 方案比较 | 至少 2 个候选，各写优点与代价；`chosen` 必须与某个候选名完全一致；选择理由非空 |
| 任务 | 至少 2 个；`id` 匹配 `[a-z0-9][a-z0-9-]*` 且全计划唯一 |
| 任务依赖 | 每项必须指向存在的任务，不许指向自己，整图不许成环 |
| 失败原因 | 每个任务至少 1 条，互相不重复 |
| 完成判定 | 每个任务必须可观察，见下节 |
| 产出 | 可为空数组；互相不重复 |
| 验证 | 至少 1 条；每条要有任务 id 或 `*`、检查内容、期望结果 |
| 验证覆盖 | 每个任务都被某条验证覆盖，或存在一条 `task: "*"` 覆盖整体 |
| 可逆性 | 布尔。`false` 表示执行前需要用户确认 |
| 置信度 | `high` / `medium` / `low` |

字段长度上限：单行字段 400 字符，多行字段 4000 字符。

## 完成判定要写成什么样

「可观察」指人或其他执行者能查证。命中下列任意一类就通过：

| 类型 | 例子 |
| --- | --- |
| 命令或退出码 | `` `pnpm test` 退出码为 0 ``、`跑 pnpm build` |
| 文件或产物 | `docs/plan.md 存在`、`report/q3.docx 不少于 20 页`、`README.md 已更新` |
| 数值或阈值 | `测试覆盖率 ≥ 80%`、`输出 42 行`、`3 条记录` |
| 对比或状态值 | `accepted 为 true`、`返回码为 0` |
| 引号里的值 | `「订单号 ABC123」已生成` |
| 他人确认或交付物 | `收到订票确认邮件`、`合同已签署`、`客户在验收单上签字` |
| 状态达成 | `页面能打开`、`样机通过跌落测试`、`已通过评审` |

会被拒绝的：

| 写法 | 拒绝原因 |
| --- | --- |
| `确认一切正常` | 只有形容词，不指向对象也不指向状态 |
| `` `好` `` | 反引号里没有实质内容 |
| `go`、`sh`、`make it happen` | 英文散文里的常见词，不构成判据 |
| `「完成」` | 引号里是中文散文而非值 |
| `随便看看`、`努力做好`、`加油` | 无判据 |
| `文档见 https://a.com` | 指向别处的链接，不是本计划可查的产物 |
| `见 example.com/notes.md` | 裸域名，不是本地文件 |

同一意思换措辞可能一边通过一边被拒：`已完成酒店预订` 通过，`酒店订好了` 被拒。这是词表匹配的已知缺陷。

## 两层拦截

| 约束 | 强度 | 触发条件 |
| --- | --- | --- |
| 缺字段、类型错、枚举非法 | **阻止** | 参数不满足 JSON Schema |
| 拼错或多写字段名 | **阻止** | 同上；`additionalProperties: false` 实际生效 |
| 空串、条目不够 | **阻止** | 内容校验 |
| 完成判定不可观察 | **阻止** | 内容校验，判据见上节 |
| 依赖成环、指向不存在的任务 | **阻止** | 内容校验 |
| 验证没覆盖全部任务 | **阻止** | 内容校验 |
| 可逆性非布尔、置信度非法 | **阻止** | 内容校验 |
| 在非模式里调用 `plan_submit` | **阻止** | 有效状态为假即抛错 |
| 计划是否真的想清楚 | 提示词 | 没有代码检查 |
| 模型跳过计划直接干活 | **不拦** | 没有守卫拦写操作 |

被拒绝时的报错带具体路径与规则，例如：

```text
计划被拒绝 — tasks[1].doneWhen: must name an observable completion — ...
修正该字段后重新提交完整计划。
```

参数形状的报错逐条列违规，最多 12 条：

```text
计划被拒绝 — arguments do not match the declared schema:
- "plan.tasks[0].done_when" is not a declared property (additionalProperties: false)
```

## 计划长什么样

通过校验后落盘并回显。文本固定九个小节：

```text
# 执行计划 revision 1

## 目标
<一句话>

## 不做（非目标）
- <不做的事>

## 约束
- [hard] <硬约束>
- [soft] <软约束>

## 方案比较
- <候选 A>**（已选）**
  - 优点：<...>
  - 代价：<...>
- <候选 B>
  - 优点：<...>
  - 代价：<...>
- 选择理由：<...>

## 任务
1. [pending] <标题>  `id: <id>`
   - 依赖：<前置任务或「无」>
   - 失败原因：<...>
   - 完成判定：<...>
   - 产出：<...>

## 验证
- [<任务id或 *>] <检查内容> → 期望：<...>

- 可逆：是 / 否
- 置信度：high / medium / low

## 执行契约
- 严格按任务顺序执行；改计划必须重新提交 `plan_submit`，不得边做边改。
- 每个任务做完立刻用它的「完成判定」验证；不通过就停下报告，不得跳过。
- 全部做完后逐条运行「验证」中的检查，把实际输出贴给用户，不要只说通过。
```

执行契约是固定文本，每次都带，不复述。

## 计划文件在哪

| 项 | 内容 |
| --- | --- |
| 路径 | `<项目锚点>/.method/plan.md` |
| 项目锚点 | 会话工作目录往上最近一个带 `.git` 的目录；找不到就用工作目录本身 |
| 主目录排除 | 用户主目录不算锚点，避免落到 `~/.method/plan.md` |
| 跟随切换 | 用户在会话中途 `cd` 后，计划落到新目录 |
| 覆盖 | 每次成功提交覆盖前一份，修订号递增 |
| 忽略 | 同目录下 `.gitignore` 不存在时自写一行 `*`，不改用户根目录的 `.gitignore` |

## 界面

| 界面 | 表现 |
| --- | --- |
| 输入框的命令菜单 | 一行 `method`，描述取命令自带的描述；没有图标 |
| 命令执行回执 | 每种状态的原文见「命令与状态」的回执列 |
| 对话流 | 只出现工具调用与用户消息；协议文本走系统提示词段落，不占对话 |
| 计划的呈现 | 工具结果里带渲染后的全文，供模型在后续步骤重读 |

## 已知限制

- **不阻止跳过计划**：`plan_submit` 只在模式里可用，但没有守卫拦写操作；模型不调它直接干活，代码拦不住。
- **完成判定靠词表匹配**：同一意思换措辞结果可能不同；`酒店订好了` 被拒而 `已完成酒店预订` 通过。方向是只看「能不能看见」，不评价「想得对不对」。
- **没有强制中断**：真正要强制得靠守卫拦写操作，代价是不开模式就不能干活，当前版本刻意不做。
- **同一项目多会话共用一份计划**：路径按工作目录定位，不含会话标识。
- **计划模式互斥是单向的**：本插件知道计划模式，反过来不知道。
- **参数形状校验依赖宿主安装目录**：解析不到宿主的校验器时只剩内容校验，拼错字段名会被静默接受。
- **没有配置项**：阈值、路径、提示词文本都是代码常量。
- **协议文本只在模式开启时注入**：关闭后零 token，但模型也不会记得协议内容。
